Вопрос 1. Каталог с правами g=x: сможет ли alice прочитать notes.txt и выполнить ls?

Ответ: Прочитать файл сможет, ls выполнить не сможет.
Почему: x на каталоге даёт право обращаться к файлам по пути, поэтому файл с известным именем открывается. r на каталоге даёт право видеть список имён, а его нет, поэтому ls выдаст Permission denied


Вопрос 2. Какая группа будет у копии report.txt в /home/alice/?

Ответ: Группа alice
Почему: cp создаёт новый файл, и создаётся он в /home/alice/. Setgid действует только на файлы, созданные внутри каталога, где он установлен. На /home/alice/ setgid нет, поэтому файл получает основную группу создателя, то есть alice


Вопрос 3. Почему «nologin + одно правило sudo» безопаснее, чем webapp в группе sudo?

Ответ: Потому что взломщик остаётся запертым в правах webapp и не может стать root
Почему:
- nologin не даёт войти на сервер как webapp через SSH или su.
- Правило sudo разрешает от root только одну команду: перезапуск своего сервиса. Максимальный ущерб — поломка одного приложения
- В группе sudo webapp мог бы выполнять любые команды от root: читать пароли, создавать пользователей, ставить бэкдоры. Это захват всего сервера

Вопрос 4. Даёт ли 777 что-то новое самому webapp по сравнению с 700? Кому 777 открыл доступ?

Ответ: Самому webapp ничего нового не даёт. Доступ открылся группе developers и всем остальным
Почему: Первая триада в 700 и 777 одинаковая (rwx), права владельца не изменились. Изменились вторая и третья:
- группа developers: rwx, теперь её участники, например alice, могут читать и менять конфиг;
- остальные: rwx, теперь это может любой пользователь и любой процесс на сервере.

Значит 777 опасен не только из-за третьей триады, но и из-за второй.
